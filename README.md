Replay a synthetic incident, see exactly why a detection rule matched, and follow the resulting alert through investigation and containment. CyberForge runs locally and includes an English and Turkish interface.

![CyberForge demo showing synthetic telemetry, matching detections, SOC alerts, the MITRE ATT&CK matrix and containment progress](docs/assets/demo.gif)

The 80-second demo replays the same incident every time. [How the demo works](docs/demo-mode.md)

## Quick start

Install Git and Docker with Compose v2. The first run downloads images and dependencies. The seeded demo runs locally without an account or API key.

```bash
git clone https://github.com/rahmankutlu/cyberforge.git
cd cyberforge
docker compose --env-file .env.example up --build --wait
```

Once the services are ready, open the [incident demo](http://localhost:3000/demo), the [dashboard](http://localhost:3000), or the [API reference](http://localhost:8000/docs). See the [setup guide](docs/getting-started.md) for Windows PowerShell, a Docker-free setup with SQLite, and shutdown commands.

## Try your first investigation

1. **Watch a synthetic incident unfold.** Open [Live demo](http://localhost:3000/demo) and press **Start demo**. Follow the telemetry, alerts and MITRE ATT&CK techniques as the incident moves toward containment.
2. **Explain a match.** Open the [Detection playground](http://localhost:3000/detections/playground), select the **Suspicious PowerShell simulation** dataset, load **PowerShell Launched With Encoded Command**, and run the rule. Pick a matched event to inspect the exact fields and condition that fired.
3. **Make the analyst's call.** Pick a case in [Attack stories](http://localhost:3000/stories), review the evidence, and choose a containment action. Use the [Mini SOC](http://localhost:3000/soc/alerts) to practice triage, notes, case assignment and incident reporting.

## Detections as code

Each shipped Sigma rule has positive and negative test cases beside its YAML file. CI runs them, including multi-event and correlation cases, and generates the coverage figures below. The workbench also translates Sigma to Splunk, Elastic, Microsoft Sentinel and OpenSearch. YARA and Suricata use teaching evaluators. [Testing detections](docs/testing-detections.md) · [Evaluator scope and translations](docs/detections.md)

## Architecture

Next.js and TypeScript serve the web app, with FastAPI handling content validation, telemetry replay and rule evaluation. Docker Compose uses PostgreSQL and Redis. Source development can use SQLite and in-memory rate limiting. The rules, labs, scenarios and datasets are versioned alongside their tests. [Architecture overview](ARCHITECTURE.md) · [OpenAPI contract](docs/api/openapi.json)

The default demos replay synthetic telemetry. Optional training services have a separate Docker profile, and published ports bind to loopback. Optional AI-assisted alert analysis requires a provider you configure. [Security model](docs/security-model.md) · [Vulnerability reporting](SECURITY.md)
